# Kasa POS feedback / issue intake

**Do not send credentials, payment secrets, customer card information or unredacted receipts.** For an unresolved payment/refund, do not retry; contact the owner/provider reconciliation contact.

- Case ID (assigned by support):
- Shop/store ID (no customer data):
- Your role: owner / manager / cashier
- Best approved callback channel and permission to follow up: yes / no
- Type: bug / usability / feature request / tax question / payment-provider issue / other
- What were you trying to do?
- What happened? Exact error text if any:
- What did you expect to happen?
- How often? First time / occasional / every time
- When did it happen? Approximate date/time in Ghana time:
- Device, operating system, browser/PWA version:
- Network: online / intermittent / offline
- Can you continue trading safely? yes / no; workaround:
- For a payment/refund: status shown in POS, amount and currency, masked provider reference only if support policy allows. **Never include PAN/CVV/PIN/OTP or full customer contact.**
- Screenshot/log: optional, only after redacting customer names, phone/email, receipt details, credentials and tokens.

## Feature request template

> “As a **[shop role]**, when **[situation]**, I need **[capability]** so that **[business outcome]**. Today I **[workaround]**. This happens **[frequency]** and costs approximately **[time/money/risk]**. It is important because **[reason]**.”

## Weekly review

At the weekly product review, group duplicates; count affected shops; assess revenue/safety/compliance impact; check whether a workaround exists; decide and document status. Do not promise a release date until the technical owner accepts it.
